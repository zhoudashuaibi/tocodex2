# 04-06 任务引擎

## 1. 职责

管理登录/刷新/查余额/设 2FA 任务的完整生命周期：DB 队列 → 并发调度 → spawn 子进程 → 解析 json-events → 自动画答人工输入点 → 代理风控重启 → 产物入库 → 回调号池模块。**替代 v1 console-server.mjs 中约 2000 行调度与 stdout 解析逻辑。**

## 2. 任务生命周期

```
创建(POST 或号池模块内部) → queued → running ⇄ awaiting_input → completed | failed | canceled
                                   ↑ 代理风控重启(spawn 新子进程, attempt+1)
```

| 状态 | 含义 | 退出条件 |
|---|---|---|
| queued | 排队等并发槽 | 引擎调度 |
| running | 子进程执行中 | 事件驱动 |
| awaiting_input | 等人工输入（自动作答源耗尽后） | `POST /jobs/:id/input` 或自动输入到达 |
| completed | 成功（login 有 result_saved；refresh 有新 token） | |
| failed | `error` 事件 / 进程异常退出 / 人工 quit | |
| canceled | 用户取消 | |

阶段 `stage` 枚举（json-events `stage` 事件透传）：`web_login / email_otp / password / mfa_otp / totp_setup_otp / about_you / add_phone / phone_otp / oauth / workspace / finalizing / refreshing`。

## 3. 调度器（engine.js）

```js
// 单事件循环内运行，无工作线程；子进程天然并行
setInterval(tick, 1000) →
  活跃数 = COUNT(jobs WHERE status IN ('running','awaiting_input'))
  while (活跃数 < max_concurrent_jobs /* settings engine.config, 默认 20，v1 MAX_ACTIVE_JOBS */
         && 有 queued 任务 /* 按 created_at FIFO，v1 语义 */) {
    job = 取队首;
    if (job.type == 'login' && 无代理 && 未做过直连指纹探测) 等共享探测结果; // v1 DirectTlsProfileProbe 语义
    launch(job);
  }
```

- **邮箱级互斥**：`idx_jobs_active_per_account` 唯一索引兜底；创建路径先 CAS 账号状态再插任务（同事务）。
- **重启恢复**（启动时单事务）：`running/awaiting_input` → `queued`（attempt 保留，error='服务重启，自动重新排队'）；子进程已死无需清理；日志文件保留续写。
- **取消**：SIGTERM 子进程（3s 后 SIGKILL）→ `canceled`；Python 孙进程随进程组终止（spawn 时 `detached:false` + 平台适配）。
- **超时看门狗**：`running` 超过 `job_timeout_minutes`（默认 30，可配）→ 记录超时并按取消处理（v1 无看门狗，是补强项）。

## 4. 子进程启动（launcher.js）

```js
const args = [
  'core/protocol-login.mjs',
  '--email', account.email,
  '--output-mode', 'codex2api',
  '--codex2api-out', `data/results/${job.id}.json`,
  '--checkpoint', `data/checkpoints/${account.id}/login.json`,
  '--resume-checkpoint', `data/checkpoints/${account.id}/login.json`,
  '--json-events', '--verbose',
];
// refresh 模式: ['--refresh-codex2api', 旧产物路径, '--codex2api-out', 新路径, '--json-events']
// totp_setup:   ['--email', ..., '--setup-totp', '--totp-result', path, '--json-events']

const env = {
  ...process.env,
  CHATGPT_PROXY_URL: proxyUrl ?? '',                 // selector.pickRandomAliveProxy() 结果
  CHATGPT_PROXY_MAX_ATTEMPTS: String(10 - job.proxy_attempts),
  CHATGPT_LOGIN_PASSWORD: credentials.password ?? '',
  CHATGPT_TOTP_SECRET: credentials.totp_secret ?? '',
  TOCODEX2_TLS_PROFILE: '',                            // 空=自动
};
const child = spawn(process.execPath, args, { cwd: serverRoot, env, stdio: ['pipe','pipe','pipe'] });
```

- **stdout 逐行解析 json-events**（§5）；**stderr 全量追加写** `data/logs/<jobId>.log`（含人类可读日志）。
- 凭据经环境变量传递（不出现在命令行，不写日志；`sanitize.js` 在落盘前对已知密钥值打码）。

## 5. 事件处理（events.js —— 纯函数表，重点单测对象）

```js
// (job, account, event) -> { jobPatch?, accountPatch?, actions?[] }
const HANDLERS = {
  starting:      (j, a, e) => ({ jobPatch: { status: 'running', started_at: now() } }),
  stage:         (j, a, e) => ({ jobPatch: { stage: e.stage } }),
  input_required:(j, a, e) => ({ actions: [{ kind: 'auto_input', event: e }] }),
  input_accepted:(j, a, e) => ({ jobPatch: { status: 'running', prompt_kind: null } }),
  proxy_session_attempt: (j, a, e) => ({ jobPatch: { proxy_attempts: e.n } }),
  risk_retry:    (j, a, e) => ({ actions: [{ kind: 'note' }] }),
  checkpoint_saved: (j, a, e) => ({ jobPatch: { checkpoint_path: e.path } }),
  result_saved:  (j, a, e) => ({ actions: [{ kind: 'save_tokens', event: e }] }),
  totp_secret:   (j, a, e) => ({ actions: [{ kind: 'save_totp', event: e }] }),
  balance:       (j, a, e) => ({ accountPatch: { balance: e.value } }),
  error:         (j, a, e) => ({ jobPatch: { status: 'failed', error: e.message },
                                 actions: [{ kind: 'classify_error', event: e }] }),
  exit:          (j, a, e) => e.ok ? { jobPatch: { status: 'completed', finished_at: now() } } : {},
};
```

- `auto_input`：见 §6。触发时若决定等待人工 → `jobPatch:{status:'awaiting_input', prompt_kind:e.kind}`。
- `save_tokens`：读 `result_saved.path` 文件 → 解析 `accounts[0].credentials` → 加密写 `accounts.tokens_enc`（若 job.type=login 且账号在备用池 → 号池模块的 join 成功回调，04-04 §3.2）。
- `classify_error`：按 03 §9 错误码表决策——`retry_proxy=true` 且会话预算未耗尽 → **引擎杀进程重启**（见 §7）；`REFRESH_TOKEN_INVALID` → 自动创建 login 任务接力（v1 `fallbackFromRefresh` 1579-1600 语义）；永久封禁 → 账号移废弃池 + `auto_repair_blocked=1`；其余 → 终态 failed。
- 子进程**非零退出且无 error 事件**（崩溃）：视为 `error{code:'INTERNAL'}` 处理，日志尾部入库。

## 6. 自动画答（auto-input.js）

`input_required(kind, detail, can_resend)` 到达时按序尝试（03 §8.4）：

| kind | 1️⃣ 自动源 | 2️⃣ 人工 |
|---|---|---|
| `email_otp` | Outlook 轮询（`credentials.outlook`，2.5s 间隔/10min，基准去重，03 §7.3）→ 泛化收码 API（`credentials.mail_api_url`，core/mail-otp.mjs） | awaiting_input |
| `password` | `credentials.password` | awaiting_input |
| `mfa_otp` / `totp_setup_otp` | `credentials.totp_secret` 本地生成（含失败重试一次的时钟偏移容错，v1 847 语义） | awaiting_input |
| `phone` | 接码平台取号（sms-providers：Luban/SMSBower/自定义号池） | awaiting_input |
| `phone_otp` | 接码平台轮询短信（只接受取号之后出现的新 6 位码） | awaiting_input |

自动源不可用/失败 → 进入 `awaiting_input`，前端任务行内联输入框（v1 JobRow 交互保留）；`POST /api/v1/jobs/:id/input` `{action:'input'|'resend'|'quit', value?}` → 校验与当前 `prompt_kind` 匹配 → 写子进程 stdin（03 §8.3）。

## 7. 代理风控重启（继承 v1 restartAfterProxyRisk，1823-1896）

触发：`error` 事件 `code ∈ {PROXY_RISK_CONTROL, PROXY_CONNECTION_RETRY}` 且 `job.proxy_attempts < 10`（有响应会话上限）。

1. 杀当前子进程。
2. 连接类错误：`fail_count` 记账到 proxies（04-03 §6）；连续失败 20 次（指数退避 1s→15s）→ 终止任务。
3. 代理支持会话轮换（`rotatable=1`）→ 同代理 `rotateProxySession` 换会话重启（新子进程，`attempt+1`，`CHATGPT_PROXY_MAX_ATTEMPTS` 递减）。
4. 代理不可轮换或已耗尽会话预算 → **换随机代理**（重新 `pickRandomAliveProxy`，v1 语义是直接失败提示换代理，v2 增强：有代理池自动换下一个）；无代理可用 → 终止并提示。
5. 重启后 `--resume-checkpoint` 复用断点（checkpoint 有效期逻辑 03 §9 `CHECKPOINT_INVALID` → 清断点完整重登一次）。

## 8. 日志

- `data/logs/<jobId>.log`：stderr 全量 + stdout 事件的时间戳化镜像（`[HH:mm:ss] <message>`，脱敏后）。追加写、不进内存。
- `GET /api/v1/jobs/:id/logs?after=<byteOffset>&limit=64KB`：增量读取（返回 `{chunk, next_offset, eof}`），前端 2s 轮询拼接。
- 终态任务保留 30 天后随 job 行清理（02 §5）。

## 9. 任务类型矩阵

| type | 子进程模式 | 产物 | 完成回调 |
|---|---|---|---|
| login | full（email_otp 或 password 路径由凭据决定） | results/<jobId>.json + tokens | 备用池 join 成功移池 / 主池 needs_reauth→active、tokens 更新 |
| refresh | `--refresh-codex2api` | 新 token 回写 tokens_enc + 产物文件原地刷新 | 同上；`REFRESH_TOKEN_INVALID` → 自动转 login |
| balance | 不起子进程（服务端直调 chatgpt-credits，随机代理） | accounts.balance | ——（也走 jobs 表以便看进度/失败，status 快速完成） |
| totp_setup | `--setup-totp` | totp_result_path → `credentials.totp_secret` | 更新凭据 + 事件 |

## 10. API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/jobs` | `?status=&account_id=&type=&page=`，含 stats `{queued,running,awaiting_input}` |
| GET | `/api/v1/jobs/:id` | 详情（含 stage/prompt_kind/error/时间戳） |
| GET | `/api/v1/jobs/:id/logs` | 增量日志 `?after=` |
| POST | `/api/v1/jobs/:id/input` | 人工输入 `{action, value}` |
| POST | `/api/v1/jobs/:id/cancel` | 取消 |
| POST | `/api/v1/jobs/:id/retry` | 失败重试（可指定 proxy_id） |
| POST | `/api/v1/jobs/cancel-all` | 取消全部活跃任务 |

任务**只能由号池操作创建**（join-main / batch-authorize / 余额批刷 / 2FA），不开放裸 POST /jobs（v1 支持手动单账号添加，v2 保留：`POST /api/v1/accounts` 单账号添加进主号池，见 05 API 规范）。
