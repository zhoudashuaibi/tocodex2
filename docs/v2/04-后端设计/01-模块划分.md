# 04-01 后端模块划分

## 1. 原则

- **一个业务域一个 Fastify 插件目录**（`server/modules/<domain>/`），路由、服务、校验 schema 都在目录内，禁止跨域直接 import 别的域的路由文件。
- 跨域共享的能力放 `fastify.decorate`（db、crypto、config、logger、jobsEngine、codex2apiClient 工厂），等价于轻量 DI。
- `server/core/` 是 v1 复用代码，**只被 jobs/codex2api/proxies 三个域引用，且只进不出**（core 不 import modules）。
- 请求体校验用 Fastify 内置 JSON Schema（可换 TypeBox 写法，编译产物相同）。

## 2. 装配顺序（index.js）

```js
import Fastify from 'fastify';
import { openDatabase } from './lib/db.js';
import { initCrypto } from './lib/crypto.js';
import { loadConfig } from './lib/config.js';

const config = loadConfig(process.env);          // 端口/数据目录/密钥来源
const db = openDatabase(config.dataDir);
const crypto = initCrypto(config);               // 加载/生成 secret.key

const app = Fastify({
  logger: pino({ level: config.logLevel }),
  trustProxy: true,                              // 反代场景取真实 IP
  bodyLimit: 2 * 1024 * 1024,                    // 批量导入文本上限 2MB
});

await app.register(async (f) => {                // 装饰器层
  f.decorate('config', config);
  f.decorate('db', db);
  f.decorate('crypto', crypto);
  f.decorate('settings', createSettingsService(db, crypto));
}, { name: 'core-decorators' });

await app.register(authModule);        // 1. auth：注册 onRequest 认证 hook
await app.register(proxiesModule);     // 2. 代理
await app.register(jobsModule);        // 3. 任务引擎（先于 accounts：accounts 依赖引擎提交任务）
await app.register(accountsModule);    // 4. 号池
await app.register(codex2apiModule);     // 5. codex2api（含监控定时器）
await app.register(settingsModule);    // 6. 设置
await app.register(dashboardModule);   // 7. 概览
await app.register(staticModule);      // 8. 前端 dist 静态托管 + SPA fallback（最后注册）

// 启动任务引擎调度循环、恢复中断任务、启动 codex2api 监控（若启用）
await app.jobsEngine.start();
await app.codex2apiMonitor.startIfEnabled();

await app.listen({ port: config.port, host: config.host });
```

**优雅关闭**（SIGINT/SIGTERM）：暂停任务队列调度 → 向所有活跃子进程发 SIGTERM（3s 后 SIGKILL）→ running/awaiting_input 任务置回 queued（attempt 保留）→ 停 codex2api 监控 → `db.close()` → `app.close()`。与 v1 shutdown 顺序语义一致（v1 console-server.mjs:4934-4995）。

## 4. 认证 hook（auth 域提供，全 API 生效）

```js
// modules/auth/index.js 内
f.addHook('onRequest', async (req, reply) => {
  if (!req.url.startsWith('/api/')) return;          // 静态资源放行
  const isPublic = req.routeOptions?.url === '/api/v1/auth/login'
                || req.url.startsWith('/api/v1/health');
  if (isPublic) return;
  const session = await verifySession(req);          // 见 04-02 §3
  if (!session) return reply.code(401).send({ error: { code: 'UNAUTHORIZED', message: '未登录或会话已过期' } });
  req.session = session;
});
```

CSRF 附加校验（写方法）：`Origin` 头必须与 Host 同源 + 请求带 `X-Requested-With: XMLHttpRequest` 头（前端 fetch 封装统一附加）。详见 [07-安全设计.md](../07-安全设计.md)。

## 5. 统一错误格式

```js
// lib/http-errors.js
export class AppError extends Error {
  constructor(status, code, message, extra = {}) { ... }
}
// 全局 setErrorHandler：
reply.status(err.status ?? 500).send({
  error: { code: err.code ?? 'INTERNAL', message: err.expose ? err.message : '服务器内部错误', ...extra }
});
```

错误码清单（全大写下划线，前端按 code 映射文案）：`UNAUTHORIZED / FORBIDDEN / VALIDATION / NOT_FOUND / CONFLICT / RATE_LIMITED / UPSTREAM_ERROR / CODEX2API_UNAVAILABLE / JOB_NOT_CANCELABLE / ACCOUNT_STATE_INVALID / POOL_TRANSFER_CONFLICT` 等。业务规则错误用 409/422，依赖 codex2api/邮箱中转的失败用 502。

## 6. settings 服务（lib 级共享）

```js
settings.get(key)                 // 返回解密后的对象（内存缓存）
settings.set(key, value, {secret}) // 加密写库 + 刷新缓存
settings.masked(key)              // 脱敏视图（给 GET 接口用）
```

启动时注入默认值（不存在才写）：`outlook.fetch`、`sms.providers`、`engine.config`、`codex2api.config`（monitor.enabled=false）。
