# 04-02 认证与会话

## 1. 需求

- 公网部署必须密码保护；**刷新页面不得要求重输密码**（30 天滑动会话）。
- 密码不明文存储、不明文出现在日志。
- 暴力破解防护：同一 IP 连续输错 5 次锁 15 分钟（继承 v1 策略）。
- CSRF 防护（Cookie 方案必须考虑）。

## 2. 密码管理

### 2.1 存储

- 哈希存 `settings` 表 key=`console.password`，值 `{ salt: <hex16>, hash: <hex128> }`，整体加密信封存储（encrypted=1）。
- 算法：`crypto.scryptSync(password, salt, 64)`（N=16384 默认参数，与 v1 console-server.mjs:78-82 一致），比较用 `crypto.timingSafeEqual`（229-238）。
- **初始化顺序**：
  1. 启动时读 settings；已有哈希 → 使用之。
  2. 无哈希且有 `TOCODEX2_CONSOLE_PASSWORD` env → 用 env 值生成哈希入库（env 只作首次种子，改密码后 env 不再生效）。
  3. 无哈希且无 env → 首个 `POST /api/v1/auth/login` 请求带 `{ new_password }` 时引导设置（前端登录页显示「设置访问密码」表单）；设好后再正常登录。此路径仅限 `password_initialized=false` 期间，且同样走限流。

### 2.2 修改密码

`POST /api/v1/auth/password` `{ current_password, new_password }`：

1. 校验当前密码（限流同 login）。
2. 新密码长度 ≥8。
3. 同一事务：更新哈希 + **删除 sessions 全部行**（改密码 = 全端登出）。
4. 为当前请求方发新会话 Cookie。

## 3. 会话（30 天滑动）

### 3.1 创建（登录成功）

```
token     = crypto.randomBytes(32).toString('base64url')     // 只出现在 Cookie，不落库
tokenHash = sha256(token) hex
INSERT INTO sessions(token_hash, created_at, expires_at=now+30d, last_seen_at=now, ip, user_agent)
Set-Cookie: tocodex2_session=<token>; Path=/; HttpOnly; SameSite=Strict; Max-Age=2592000[; Secure]
```

- `Secure` 标志：`trustProxy` 下依据 `x-forwarded-proto === 'https'` 判定（Fastify 自动），或 env `TOCODEX2_FORCE_SECURE_COOKIE=1` 强制。
- 登录成功**总是新 token**（不复用旧 Cookie，防会话固定）。

### 3.2 校验（onRequest hook 每请求）

```
1. 读 Cookie tocodex2_session → 无 → 401
2. sha256(token) 查 sessions → 无或 expires_at < now → 401（顺带 DELETE 过期行）
3. 滑动续期：last_seen_at 距 now > 5 分钟才写库（减少写放大）：
   expires_at = max(expires_at, now + 30d), last_seen_at = now
```

> 滑动语义：只要 30 天内访问过一次就一直有效；连续 30 天不打开才过期。

### 3.3 撤销

- `POST /api/v1/auth/logout`：删除当前 token_hash 行 + 清 Cookie（Max-Age=0）。
- `POST /api/v1/auth/logout-all`：`DELETE FROM sessions`（设置页「登出所有设备」）。
- `GET /api/v1/auth/session`：返回 `{ authenticated, password_initialized, expires_at, sessions_count }`，前端启动时探测（未登录 200 + authenticated=false，而非 401，便于路由决策）。

### 3.4 Cookie 属性依据

| 属性 | 值 | 理由 |
|---|---|---|
| HttpOnly | ✓ | 防 XSS 读取 |
| SameSite | Strict | CSRF 主防线；同源部署无跨站携带需求 |
| Secure | 自动/强制 | HTTPS 反代下必须 |
| Path | / | API 与页面同源同路径 |
| Max-Age | 2592000 | 30 天，与服务端 expires_at 一致 |

## 4. 登录限流（跨重启）

v1 限流在内存（重启清零）。v2 落 `login_attempts` 表：

```
失败: fail_count+1；fail_count>=5 → locked_until=now+15min
成功: DELETE 该 ip 行
锁定中请求: 429 { retry_after_seconds }（不消耗 fail_count）
判定用 UPDATE ... WHERE 返回行数保证原子
```

限流对象 IP 取法：`trustProxy: true` 下 Fastify `req.ip` 已按 x-forwarded-for 首段解析（与 v1 243-247 一致）。**注意**：直连暴露部署时 x-forwarded-for 可伪造，锁定可被绕过为「换假 IP」——公网正确姿势是必须挂反代，文档在部署篇强调。

## 5. CSRF 防护（双保险）

1. `SameSite=Strict`：跨站请求不携带 Cookie（主防线）。
2. 写方法（POST/PUT/PATCH/DELETE）额外校验：
   - `Origin` 头存在时必须与请求 Host 同源；
   - 必须带 `X-Requested-With: XMLHttpRequest` 头（前端 `apiFetch` 统一附加，表单无法自然携带）。

GET 一律只读、不产生副作用（列表/导出走 GET + 参数），导出文件下载也走 GET 带 Cookie。

## 6. API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/auth/login` | `{password}` 或首设 `{new_password}` → Set-Cookie |
| POST | `/api/v1/auth/logout` | 注销当前会话 |
| POST | `/api/v1/auth/logout-all` | 注销全部会话 |
| GET | `/api/v1/auth/session` | 会话探测 |
| POST | `/api/v1/auth/password` | 修改密码（全端登出+重发会话） |
| GET | `/api/v1/auth/sessions` | 活跃会话列表（ip/ua/last_seen，供设置页） |

请求/响应示例见 [05-API接口规范.md](../05-API接口规范.md#1-认证-auth)。

## 7. 与 v1 的差异

| 项 | v1 | v2 |
|---|---|---|
| 令牌载体 | 进程内存 `consoleToken`，前端 localStorage-ish 内存持有，手动加 header | HttpOnly Cookie，浏览器自动携带 |
| 刷新行为 | 重新输密码 | 30 天内无感 |
| 重启 | 全部会话失效 | 会话保留 |
| 限流 | 内存，重启清零 | DB 持久 |
| 密码来源 | 仅 env，无法从 UI 修改 | DB 为主，env 首次种子，UI 可改 |
