# 08 部署与运维

## 1. 部署形态

单容器同源：一个镜像包含 Node 后端 + Python(curl_cffi) + 前端构建产物；`/api/*` 与页面同端口；公网部署前置 Nginx/Caddy 终结 HTTPS。

## 2. Dockerfile（多阶段）

```dockerfile
# ---------- 前端构建 ----------
FROM node:22-bookworm-slim AS web-build
WORKDIR /app/web
COPY web/package*.json ./
RUN npm ci
COPY web ./
RUN npm run build          # 产物 → /app/../server/web-dist（见 06-01 outDir 配置）

# ---------- 运行镜像 ----------
FROM node:22-bookworm-slim
RUN apt-get update \
 && apt-get install -y --no-install-recommends python3 python3-pip tini \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY server/package*.json ./
RUN npm ci --omit=dev
COPY server ./
COPY --from=web-build /app/web-dist ./web-dist
RUN pip3 install --no-cache-dir --break-system-packages curl_cffi==0.15.0 \
 && mkdir -p /app/data \
 && chown -R node:node /app
USER node
ENV TOCODEX2_DATA_DIR=/app/data \
    TOCODEX2_WEB_DIST=/app/web-dist \
    NODE_ENV=production
EXPOSE 1999
HEALTHCHECK --interval=30s --timeout=5s \
  CMD node -e "fetch('http://127.0.0.1:1999/api/v1/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
ENTRYPOINT ["/usr/bin/tini", "--"]
CMD ["node", "index.js"]
```

要点：tini 做 PID 1 转发信号（优雅关闭依赖，v1 已用）；非 root 运行；curl_cffi 与 v1 requirements.txt 同版本。

## 3. docker-compose.yml

```yaml
services:
  tocodex2:
    image: ghcr.io/<owner>/tocodex2:v2        # 或 build: .
    restart: unless-stopped
    ports:
      - "127.0.0.1:1999:1999"               # 只绑本机，由反代转发；确需直连再改 0.0.0.0
    volumes:
      - ./data:/app/data
    environment:
      TOCODEX2_CONSOLE_PASSWORD: ${TOCODEX2_CONSOLE_PASSWORD:-}   # 首次种子，可留空走首访引导
      TOCODEX2_SECRET_KEY: ${TOCODEX2_SECRET_KEY:-}               # 建议显式提供
      TOCODEX2_PORT: "1999"
    mem_limit: 1g
```

`.env`（git 忽略）：`TOCODEX2_CONSOLE_PASSWORD=强密码`、`TOCODEX2_SECRET_KEY=<openssl rand -base64 32>`。

volume 属主：宿主 `mkdir data && chown 1000:1000 data`（容器内 node 用户 uid=1000）。

## 4. 反代示例

```nginx
server {
  listen 443 ssl http2;
  server_name tocodex2.example.com;
  ssl_certificate     /etc/letsencrypt/live/.../fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/.../privkey.pem;

  location / {
    proxy_pass http://127.0.0.1:1999;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_read_timeout 120s;      # codex2api 上传长请求
  }
}
```

## 5. 环境变量总表

| 变量 | 默认 | 说明 |
|---|---|---|
| `TOCODEX2_DATA_DIR` | `./data`（容器 /app/data） | SQLite/密钥/日志/断点/产物根目录 |
| `TOCODEX2_PORT` / `TOCODEX2_HOST` | 1999 / 127.0.0.1（容器 0.0.0.0） | 监听 |
| `TOCODEX2_CONSOLE_PASSWORD` | - | 首次密码种子（入库后不再生效） |
| `TOCODEX2_SECRET_KEY` | 自动生成 secret.key | 加密主密钥 |
| `TOCODEX2_FORCE_SECURE_COOKIE` | - | `1` 强制 Cookie Secure |
| `TOCODEX2_PYTHON` | 自动探测 | 指定 Python 解释器（裸机部署用） |
| `TOCODEX2_TLS_PROFILE` | - | 强制 TLS 指纹（调试用） |
| `TOCODEX2_LOG_LEVEL` | info | pino 级别 |

## 6. 裸机运行（可选）

```bash
npm ci && npm --workspace web run build
python3 -m pip install -r requirements.txt
node server/index.js        # 或 pm2 start（沿用 v1 ecosystem.config.cjs 形式）
```

## 7. 备份与恢复

**备份**（在线，安全）：

```bash
node scripts/backup.mjs /path/to/backup-dir
# 内部：db.backup()（SQLite backup API，WAL 安全）+ 复制 checkpoints/ + results/ + secret.key（可选 --with-secret）
```

**恢复**：停容器 → `data/` 换回备份内容（含 secret.key，否则密文解不开）→ 起容器（迁移器自动补 schema）。

**备份频率建议**：日备；`data/results/` 增长可控（每账号一个 JSON，几 KB）。

## 8. 升级

```bash
docker compose pull && docker compose up -d    # 数据卷不动
```

启动时自动跑迁移（02 §6）；跨大版本先看 CHANGELOG 是否要求新 env（如 v2 首次需要 SECRET_KEY）。

## 9. 日常运维

- 日志：`docker compose logs -f`（pino JSON）；任务级日志在页面任务中心看，文件在 `data/logs/`。
- 磁盘：`data/logs` 随 30 天保留策略自动清理；`data/results` 随账号删除清理；监控大盘可加磁盘占用展示（可选）。
- 健康检查：`GET /api/v1/health`（免认证）返回 version/uptime，uptime 波动重启即知。
- 常见故障：
  | 现象 | 排查 |
  |---|---|
  | 登录后立刻 401 | Cookie 未带 Secure 但走 https / 时钟漂移（expires_at 判定） |
  | 任务全部 queued 不跑 | Python/curl_cffi 缺失（`TOCODEX2_PYTHON` 指错）；看 stderr 日志 |
  | 余额批量失败 401 | refresh_token 失效 → 先批量授权 |
  | 上传 502 | codex2api 不可达/密钥错；页面「测试连接」 |
