# 07 安全设计

系统部署在公网，持有大量账号凭据与 OAuth token，安全设计是第一优先级。

## 1. 威胁模型

| # | 威胁 | 对策 | 落点 |
|---|---|---|---|
| 1 | 未认证访问 API / 页面 | 全 `/api/*` 会话校验 hook（除 login/session/health） | 04-01 §4 |
| 2 | 密码暴力破解 | scrypt 哈希 + timingSafeEqual；IP 限流 5 次/15 分钟（DB 持久） | 04-02 |
| 3 | 明文传输被嗅探 | 强制建议 HTTPS 反代；Cookie 自动/强制 Secure | 08 |
| 4 | CSRF | SameSite=Strict + Origin 校验 + X-Requested-With 头 | 04-02 §5 |
| 5 | XSS 窃取会话 | HttpOnly Cookie（JS 不可读）；React 默认转义；不使用 dangerouslySetInnerHTML | 04-02 §3 |
| 6 | 数据库文件被拖走（备份泄露/目录穿越） | 敏感字段 AES-256-GCM 加密，密钥不在库中 | §2 |
| 7 | codex2api admin_key 泄露 | 只写不读（GET 掩码）、不入 localStorage、不入日志 | §4 |
| 8 | 日志泄露凭据 | 统一脱敏过滤器，已知密文值打码 | §3 |
| 9 | 会话固定/长窃取 | 登录发新 token；30 天上限；改密全端登出；会话列表可自查 | 04-02 |
| 10 | 子进程命令行泄露凭据 | 密码/TOTP/代理经 env 传递，不进 argv（ps 不可见） | 04-06 §4 |

## 2. 密钥与加密

### 2.1 密钥来源（优先级）

1. `TOCODEX2_SECRET_KEY` 环境变量（推荐：Docker secret / compose env；32 字节 base64 或任意字符串经 sha256 派生）。
2. 无 env → 自动生成 32 字节随机密钥写 `data/secret.key`（权限 0600），并打日志提醒「建议改用环境变量以便备份/迁移」。

**密钥轮换**：更换密钥后旧密文无法解密（启动时解密失败的字段视为损坏并要求重新录入），文档明确不提供在线轮换。

### 2.2 加密信封（lib/crypto.js）

```
encrypt(plaintext, key):
  iv   = randomBytes(12)
  cipher = aes-256-gcm(key, iv)
  ct   = cipher.update(plaintext,'utf8') + cipher.final()
  tag  = cipher.getAuthTag()
  return `v1:${iv.toString('base64')}:${tag.toString('base64')}:${ct.toString('base64')}`
```

AAD 绑定字段用途（防跨字段替换攻击）：`cipher.setAAD(Buffer.from(fieldPath))`，fieldPath 如 `accounts.tokens_enc` / `settings.codex2api.config`。

### 2.3 加密字段清单

| 字段 | 内容 |
|---|---|
| `accounts.credentials_enc` | 登录密码 / TOTP 密钥 / 收码 API / Outlook 凭据 / 固定代理 URL |
| `accounts.tokens_enc` | access/refresh/id token |
| `proxies.url_enc` | 完整代理 URL（含账密） |
| `settings` encrypted=1 行 | console.password 哈希、codex2api.config（含 admin_key）、接码平台 api_key |

### 2.4 口令哈希

`scrypt(password, salt(16B), 64)` + `timingSafeEqual`（继承 v1 console-server.mjs:78-82, 229-238）。哈希本身再走 §2.2 加密存 settings。

## 3. 脱敏规则（lib/sanitize.js）

所有日志（pino、任务日志文件、API 错误响应）落盘/返回前过滤：

1. **值替换**：内存中维护「本进程已知的敏感值集合」（密码、TOTP、token、admin_key、代理 URL 的账密段），出现即替换为 `***`。任务日志在写入 `data/logs/*.log` 前过滤。
2. **模式替换**：正则兜底——`Bearer\s+[\w.-]+`、`sk-[A-Za-z0-9]{8,}`、`(access|refresh|id)_token["']?\s*[:=]\s*["'][^"']+`、`[a-z]+://[^/@:\s]+:[^@/\s]+@`（代理 URL 账密）。
3. **代理展示**：统一 `display_url`（`http://user:***@host:port`）。
4. job 的 `error` 字段入库前过同一过滤器。

## 4. 只写不读字段（API 层）

| 字段 | GET 返回 | PUT 语义 |
|---|---|---|
| codex2api `admin_key` | `sk-****abcd`（尾 4 位） | 空串或 `****` = 不修改 |
| 接码平台 `api_key` | 同上 | 同上 |
| 账号凭据 | 永不返回（仅 `has_password/has_totp` 布尔） | 导出 source 格式时按需显式请求且记 audit |

## 5. 文件权限

| 路径 | 权限 | 内容 |
|---|---|---|
| `data/secret.key` | 0600 | 加密密钥 |
| `data/tocodex2.db` | 0600 | 含密文 |
| `data/logs/*.log` | 0600 | 任务日志（已脱敏，仍按敏感处理） |
| `data/results/*.json` | 0600 | **含明文 OAuth token**（codex2api 导入文件），等价于密码文件 |
| `data/checkpoints/**` | 0600 | 含 CookieJar（v1 同样 0600，protocol-login.mjs:1798-1801） |

Docker 内以非 root 用户（uid 1000）运行，volume 属主一致（08 §2）。

## 6. 传输安全

- 公网部署**必须**前置 Nginx/Caddy 做 HTTPS（文档醒目提示；v1 README 同样要求）。
- `trustProxy: true` 使 Fastify 以 x-forwarded-for 为客户端 IP（限流依据）——**直连暴露 + 伪造 XFF 可绕过 IP 限流**，因此部署文档写明：禁止绕过反代直接暴露端口（云安全组只放行反代来源）。
- Cookie `Secure` 自动跟随 `x-forwarded-proto`，或 `TOCODEX2_FORCE_SECURE_COOKIE=1` 强制。

## 7. 依赖与供应链

- 后端运行时依赖刻意极少：fastify、better-sqlite3、pino（+v1 核心零依赖）。前端走 shadcn/ui 生成式组件（复制进仓库，不引入组件库运行时依赖）。
- `npm ci` + lockfile 提交；Docker 构建用固定基础镜像 digest 可后续加。

## 8. 审计

- `account_events` 记录所有账号级动作（谁触发不区分——单管理员；但记录来源 `source: 'api'|'monitor'|'auto_repair'`）。
- 登录成功/失败、密码修改、会话登出写 pino 结构化日志（含 IP）。

## 9. 安全自查清单（上线前）

- [ ] `TOCODEX2_CONSOLE_PASSWORD` 已设置（或首访引导完成）
- [ ] HTTPS 反代生效，`GET /auth/session` 响应 Cookie 带 `Secure`
- [ ] 未认证 `GET /api/v1/jobs` 返回 401
- [ ] `data/` 内文件权限 0600、属主为运行用户
- [ ] 备份文件不含 `secret.key` 明文时无法解密库内密文（演练验证）
- [ ] `GET /codex2api/config` 不回明文 key；`GET /proxies` 不回明文代理
- [ ] 改密码后其他设备访问返回 401
