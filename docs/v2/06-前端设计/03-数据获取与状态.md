# 06-03 数据获取与状态管理

## 1. 原则

- **服务端状态全部走 TanStack Query**；不写全局 Redux/Zustand 业务 store（仅 UI 偏好用 zustand：主题、侧栏折叠）。
- 轮询集中在 query 的 `refetchInterval`，页面不可见时自动暂停（`refetchIntervalInBackground: false` 默认行为）。
- 乐观更新只用于低风险开关（监控启停）；表格数据一律 mutation 成功后 invalidate 重取。

## 2. fetch 封装（api/client.ts）

```ts
const BASE = '/api/v1';

export async function api<T>(path: string, init?: RequestInit & { json?: unknown }): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    method: init?.method ?? (init?.json !== undefined ? 'POST' : 'GET'),
    headers: {
      'X-Requested-With': 'XMLHttpRequest',            // CSRF 二 factor（后端强制）
      ...(init?.json !== undefined ? { 'Content-Type': 'application/json' } : {}),
      ...init?.headers,
    },
    body: init?.json !== undefined ? JSON.stringify(init.json) : init?.body,
    credentials: 'same-origin',                        // Cookie 同源携带
  });
  if (res.status === 401) {
    queryClient.clear();                               // 丢弃缓存，避免旧数据闪现
    router.navigate({ to: '/login' });
    throw new ApiError('UNAUTHORIZED', '登录已过期');
  }
  if (!res.ok) {
    const body = await res.json().catch(() => null);
    throw new ApiError(body?.error?.code ?? 'UNKNOWN', body?.error?.message ?? `HTTP ${res.status}`);
  }
  return res.json();
}
```

## 3. Query Key 约定与轮询表

```ts
export const qk = {
  session: ['session'],
  dashboard: ['dashboard'],
  proxies: (f: ProxyFilter) => ['proxies', f],
  accounts: (pool: Pool, f: AccountFilter) => ['accounts', pool, f],
  accountEvents: (id: number) => ['accounts', id, 'events'],
  jobs: (f: JobFilter) => ['jobs', f],
  job: (id: string) => ['jobs', id],
  jobLogs: (id: string, offset: number) => ['jobs', id, 'logs', offset],
  codex2apiConfig: ['codex2api', 'config'],
  codex2apiMonitor: ['codex2api', 'monitor'],
  settings: ['settings'],
};
```

| Query | refetchInterval | 触发条件 |
|---|---|---|
| dashboard | 30_000 | 常开 |
| accounts(reserve) | 10_000 | 页面聚焦 |
| accounts(main) | 10_000 | 页面聚焦 |
| accounts(discard) | 30_000 | 页面聚焦 |
| jobs | 2_000 | 任务中心聚焦 |
| jobLogs | 2_000 | 日志面板展开且未 eof |
| codex2apiMonitor | 30_000 | codex2api 页聚焦 |
| proxies | 3_000（仅存在 testing 状态时）/ 30_000 | 测活进行中加快 |
| session / settings / codex2apiConfig | 0（不轮询） | 按需 |

> v1 前端轮询为 900ms 任务 + 10s 备用池（main.jsx:35,220-235）。v2 任务列表放宽到 2s（事件流改造后服务端状态更稳定，且日志已不随列表返回），可实测后回调。

## 4. Mutation 模式

```ts
// 例：批量上传
const utils = useQueryClient();
const upload = useMutation({
  mutationFn: (body: UploadBody) => api('/accounts/batch-upload-codex2api', { json: body }),
  onSuccess: (res) => {
    toast.success(`上传完成：新增 ${res.created}，替换 ${res.updated}` +
      (res.failed.length ? `，失败 ${res.failed.length}` : ''));
    if (res.failed.length) openResultDialog(res.failed);
    utils.invalidateQueries({ queryKey: ['accounts', 'main'] });
  },
  onError: (e) => toast.error(e.message),
});
```

invalidate 矩阵（成功后必须失效的 key）：

| 操作 | invalidate |
|---|---|
| 导入备用池 / join-main / refresh-mail | accounts(reserve), dashboard |
| batch-authorize / retry / cancel / input | jobs, accounts(main), dashboard |
| batch-refresh-balance | accounts(main)（轮询自然刷新亦可） |
| batch-upload-codex2api | accounts(main), dashboard, codex2apiMonitor |
| batch-discard / restore / delete | 对应 accounts(pool), dashboard |
| 代理导入/测试/删除 | proxies, dashboard |
| codex2api config / monitor | codex2apiConfig, codex2apiMonitor, dashboard |
| 设置修改 | settings, dashboard |

## 5. 表格选中状态

`useTable-selection.ts`：每页组件本地 `useState<Set<number>>`（行 id），跨页保留（服务端分页下「全选」仅选当前页并提示）；批量操作完成后清空选中。不进全局 store。

## 6. 日志查看器（log-viewer）

- 维护 `offset` state；`useQuery(qk.jobLogs(id, offset))` → 追加 chunk → `offset = next_offset`。
- `eof` 后停止轮询；用户手动滚动检测：若滚动条不在底部则暂停自动滚底，出现「回到底部」悬浮按钮。
- chunk 以追加渲染（`<pre>` 分段数组，避免超大字符串重排）；单任务日志上限 5MB，超出前端截断头部并提示。

## 7. 错误与 401 处理

- `ApiError` 携带 code；常见 code → 文案映射表（`UNAUTHORIZED=登录已过期` `RATE_LIMITED=操作过于频繁` `CODEX2API_UNAVAILABLE=codex2api 连接失败` …），未匹配显示后端 message。
- 全局 `QueryCache.onError`：网络错误（TypeError: Failed to fetch）→ toast「网络异常，请检查服务是否可达」。
- 401 统一在 client 层跳登录（§2），组件不用单独处理。
